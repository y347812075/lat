# SPECint2000 AOT validation

The validation uses the static x86-64 executables from
`specbin/x64_gcc12_2_0` and the official SPEC test workloads. A profile bundle
is run first with `LATC_PROFILE_OUT`; the resulting program addresses are fed
to `compile-aot.sh`. The final output is then run by `runspec` with strict AOT
checking enabled.

Validated on 2026-08-20 on LoongArch 3A6000:

| benchmark | final TBs | profile TBs | AOT bytes | program JIT | system JIT | SPEC test |
|---|---:|---:|---:|---:|---:|---|
| 164.gzip | 38,372 | 21 | 10,372,928 | 0 | 0 | PASS |
| 175.vpr | 49,645 | 32 | 13,455,200 | 0 | 0 | PASS |
| 176.gcc | 142,222 | 47 | 38,144,040 | 0 | 0 | PASS |
| 181.mcf | 42,239 | 24 | 11,383,904 | 0 | 0 | PASS |
| 186.crafty | 51,507 | 29 | 14,064,336 | 0 | 0 | PASS |
| 197.parser | 53,873 | 26 | 14,428,176 | 0 | 0 | PASS |
| 252.eon | 107,398 | 30 | 28,807,680 | 0 | 0 | PASS |
| 253.perlbmk | 85,333 | 31 | 22,918,608 | 0 | 2 | PASS |
| 254.gap | 70,946 | 26 | 19,121,944 | 0 | 0 | PASS |
| 255.vortex | 72,211 | 28 | 19,765,928 | 0 | 4 | PASS |
| 256.bzip2 | 37,502 | 22 | 10,173,312 | 0 | 0 | PASS |
| 300.twolf | 52,583 | 24 | 14,311,936 | 0 | 0 | PASS |

`program JIT` counts generated PCs inside the input ELF's executable sections.
`system JIT` counts generated PCs outside those sections. Perlbmk and vortex
execute guest VDSO/signal helper code around `0x5508004500`; that anonymous
mapping is not currently represented by LAT's file-backed AOT segment format.

Use full strict mode when no system TB is expected:

```sh
LATC_STRICT_AOT=1 LATC_STATS_OUT=stats.json ./program.la64 arguments...
```

For programs using guest VDSO/signal helper pages, require the main executable
to be fully AOT while retaining the explicit system JIT fallback:

```sh
LATC_STRICT_PROGRAM_AOT=1 LATC_STATS_OUT=stats.json ./program.la64 arguments...
```

The essential passing conditions are:

```text
pretranslated = 0
runtime_tb_gen_attempts = 0
runtime_program_tb_gen_attempts = 0
```

## Train validation and performance

`prepare-specint-train.py` runs the official train workload, builds an embedded
AOT image, then repeats strict execution until all observed main-program PCs
are present. `254.gap` needed two supplemental addresses. Profile addresses
outside the input ELF are rejected by default; this script opts in to ignoring
them for `perlbmk` and `vortex`, whose guest VDSO pages remain explicit system
fallbacks.

Validated on Loongnix 20, kernel 4.19.0-19-loongson-3, LoongArch 3A6000. Each
program used one warmup followed by five alternating runs pinned to CPU 2. The
baseline is the exact LAT runner embedded in the bundle, run with `LATX_AOT=1`.

| benchmark | latc median (s) | LAT AOT median (s) | speedup | main attempts | system attempts |
|---|---:|---:|---:|---:|---:|
| 164.gzip | 9.901749 | 9.851800 | 0.9950x | 0 | 0 |
| 175.vpr | 6.038113 | 6.043449 | 1.0009x | 0 | 0 |
| 176.gcc | 1.139502 | 1.110083 | 0.9742x | 0 | 0 |
| 181.mcf | 3.636358 | 3.633203 | 0.9991x | 0 | 0 |
| 186.crafty | 6.215199 | 6.175257 | 0.9936x | 0 | 0 |
| 197.parser | 2.132316 | 2.104014 | 0.9867x | 0 | 0 |
| 252.eon | 2.194876 | 2.100561 | 0.9570x | 0 | 0 |
| 253.perlbmk | 18.588610 | 20.053171 | 1.0788x | 0 | 6 |
| 254.gap | 1.697309 | 1.808801 | 1.0657x | 0 | 0 |
| 255.vortex | 2.964398 | 3.665349 | 1.2365x | 0 | 4 |
| 256.bzip2 | 9.094530 | 9.040102 | 0.9940x | 0 | 0 |
| 300.twolf | 3.697945 | 3.627171 | 0.9809x | 0 | 0 |

Geometric mean speedup is **1.0195x**. All 60 measured bundle runs hit the
validated AOT cache. The main executable generated no runtime TB in any run.
The `perlbmk` and `vortex` system counts are translator-entry attempts per
strict validation run; they do not indicate main-program JIT. Across the 60
measured runs there were 50 system attempts and 30 installed system TBs.

These numbers compare two different AOT construction paths: latc generates an
AOT image from its CFG and observed missing targets, while the baseline uses
LAT's normal runtime-driven AOT cache. The result therefore measures the whole
output, not only bundle startup overhead. It is evidence for static main-program
execution, but not evidence that the output is independent of LAT.

Profile data is tied to the exact guest ELF hash and workload. Regenerate it
after changing the x86 binary, LAT code generator, optimization options, or
SPEC input size. A strict failure PC inside an executable section should be
added to the profile and the AOT output rebuilt; this was required twice for
254.gap.

## Native image prototype

The first stable native-image export was validated for `164.gzip` on the same
Loongnix 20 host. Two consecutive exports from the same runner, guest, and
profile produced the same SHA-256:

```text
image bytes: 6,587,520
guest bytes: 899,936
LoongArch code bytes: 2,623,952
TB records: 38,372
relocation records: 66,953
SHA-256: a613c175afa61a498c52dd327fe6b1429e335090c5389d3762366682c0edeb49
LAT build ID: lat-42c042301e107b34063773e118c825dd644d476c-x64-v1
```

`latc inspect-native` validates all file ranges, `(guest_pc, flags)` ordering,
TB code ranges, relocation slots, and runtime-symbol IDs. LAT's process-local
TU search data is removed because it contains host pointers.

This file is not executable. It is the input for the next step: apply stable
relocations, link the minimal runtime and guest load image into a LoongArch
PIE, then run the official gzip test and train workloads. Precise recovery from
an arbitrary signal PC is also pending because the removed LAT search data has
not yet been replaced by a stable PC map.

The first LoongArch PIE shell has also been linked natively on Loongnix 20. It
uses `/lib64/ld.so.1`, depends only on `libc.so.6`, embeds the image in
`.latc.image`, and maps gzip's x86 ELF range at `0x400000-0x51c000` with entry
`0x401cb0`. It deliberately exits with status 126 on normal startup because
guest state setup, real runtime helpers, and translated-code entry are not
implemented yet.

The shell now also applies all 66,953 gzip relocations to a private code copy
and changes it from RW to RX. This validates the LoongArch instruction rewrite
and address ranges, but the runtime helper and epilogue symbols still point to
abort placeholders, so it remains unsafe to enter translated code.

Before attempting any SPEC program, the runtime executed a separate two-TB
static x86 fixture containing only `exit(42)`. LAT-generated LoongArch code ran
and reached the extracted x86 Linux syscall layer, which read x86 `RAX` and
`RDI` from the LAT environment and terminated with status 42. Native image
generation now accepts any validated static x86-64 ELF without `PT_INTERP`;
the runtime still requires the recorded LAT build ID to match.

### Direct static gzip execution

Validated on 2026-08-21 on the AOSC LoongArch 3A6000 host. The input was the
static x86-64 `gzip_base.Of.gcc830.dyn` executable and the official SPEC2000
test workload `input.compressed 2`.

```sh
tools/latc/scripts/compile-native-elf.sh \
  tools/latc/build/latc runner-build/latx-x86_64 \
  gzip_base.Of.gcc830.dyn gzip-static.la64
./gzip-static.la64 input.compressed 2 > output
cmp output input.compressed.out
```

The generated file is a 7,332,048-byte LoongArch PIE. It contains 38,672
translated TBs, 2,661,312 bytes of LoongArch code, and 83,164 relocations. Two
consecutive executions exited with status 0, produced no stderr, and matched
the 987-byte reference output byte for byte. The output SHA-256 was
`162841eda1a375560df7a597aa04638016d0429e27401a0106e9bbfc7cffff20`.

This path does not start `latx-x86_64` at runtime and has no runtime JIT. It
maps the embedded x86 load segments, enters the pre-generated LoongArch code,
and resolves indirect branches through the embedded TB table. The executable
still dynamically depends on the host LoongArch `libc.so.6` and loader; it is
not yet a fully static LoongArch ELF.

The minimal runtime now covers the gzip test workload's `readlink`,
`newfstatat`, CPUID/cache discovery, and both direct and indirect TB exits.
Floating-point status conversion remains intentionally conservative: the
current no-op wrappers are valid for this integer workload but are not a
complete x87 or non-default SSE rounding implementation. Test and train
workloads for other SPEC programs still need separate native-ELF validation.
